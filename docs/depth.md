# Реконструкция глубины

`DepthService` строит единое облако точек в системе координат камеры-рига по откалиброванным стереопарам AB, BC и AC. Контракт запроса версии 1 содержит три 8-битных кадра в градациях серого и calibration bundle. Для каждой пары в нём передаются фокусные расстояния, длина базиса, преобразование в систему координат рига и URI карты ректификации.

CPU-реализация выполняет горизонтальный блочный поиск соответствий на ректифицированных кадрах, проверку согласованности слева направо и справа налево, фильтрацию спеклов по связным компонентам, а также оценку confidence по уникальности и фотометрическому качеству совпадения. Для каждого пикселя сервис рассматривает результаты всех допустимых базисов, отбрасывает значения глубины вне настроенного рабочего диапазона и выбирает вариант с наилучшим сочетанием достоверности и пригодности disparity. Нулевой confidence используется как признак невалидного пикселя.

Выбранные карты глубины объединяются в общее облако точек с применением поворота и смещения из калибровки. Результат сохраняется в виде PLY-файла, а карта достоверности — в формате PGM.

Ответ содержит только событие `PointCloudCreated`, счётчики валидных и невалидных точек и статистику выбора базисов. Облако точек и карта confidence загружаются в `StorageService` по путям `depth/point-cloud.ply` и `depth/confidence.pgm`. В контракт и сообщения NATS передаются URI сохранённых артефактов, а не их бинарное содержимое.

## Бэкенды

- `Depth:Backend=Cpu` — переносимая резервная реализация, используемая по умолчанию.
- `Depth:Backend=Native` — изолированная точка интеграции с `libsmartmetrix_stereo` на базе OpenCV CUDA/VPI. Пока нативная библиотека не развёрнута, вызов завершается явной ошибкой `StereoBackendNotConfiguredException` с рекомендацией выбрать CPU-бэкенд или установить библиотеку.

Нативная библиотека отвечает за аппаратно-зависимую ректификацию и ускоренное построение disparity. Её результат обязан соответствовать тому же контракту `DisparityMap`: каждый пиксель должен иметь confidence либо признак невалидности. Благодаря этому переключение бэкенда не меняет API сервиса и контракты событий.

## Проверка

Синтетический тест проверяет совместную обработку базисов 0,7, 0,8 и 1,5 м одной версией контракта, наличие invalid marker, сохранение результатов по URI и соблюдение заданного бюджета ошибки глубины.
