# План завершения веб-сервисов SmartMetrix — 30.09.2026

Назначение: тикеты GitHub в ATitov/SmartMetrix. Пользователь подтвердил публикацию в этом репозитории. Повторная попытка создания issue получила от GitHub HTTP 403 «Resource not accessible by integration»: подключённой интеграции недоступна запись Issues. Новые issues не созданы, roadmap #20 не изменён. Требуется предоставить интеграции доступ Issues: Read and write к ATitov/SmartMetrix. Исходные задачи #1–19 закрыты, открыта дорожная карта #20. Ниже — последующие работы, а не повтор исходной реализации. Оценка по локальному коду, включая незакоммиченные изменения StoneVision; при исполнении сверить с main.

## Очерёдность

### Выполнено локально 30.09.2026: программная проверка StoneVision → BlockAnalysis

- Проверена существующая передача instanceMap через оркестратор до анализа блоков.
- HTTP E2E усилен двумя соприкасающимися масками: оба sourceInstanceId доходят до анализа, ссылка на instanceMap сохраняется в provenance.
- Исправлена обработка некорректной структуры ответа readiness StoneVision; добавлены проверки null, массива, строкового флага и невалидного JSON.
- Исправлена документация сегментации: детерминированный backend не исполняет ONNX/TensorRT, StoneVision не распознаёт трещины.
- `dotnet test SmartMetrix.sln --no-restore --configuration Release`: 130 пройдено, 0 ошибок, 0 пропущено.
- `dotnet format SmartMetrix.sln --no-restore --verify-no-changes`: успешно.
- HTTP E2E использует тестовый ответ StoneVision и симулятор камеры. Реальные веса, GPU-инференс и полевая точность ещё не приняты; соответствующие задачи полностью не закрыты. Изменения локальные, без публикации PR.

1. P0: принять синхронный захват и калибровку; параллельно завершить StoneVision и подготовить источники позы.
2. P0: принять качество и глубину, затем расчёт блоков и геопривязку; реестр реперов подготовить до геодезической приёмки.
3. P0: соединить TriggerService с MeasurementOrchestrator и проверить восстановление полного цикла.
4. P1: принять MinIO/backup, CloudSync и диагностику ApiGateway. Облачная интеграция не блокирует первый локальный E2E; она обязательна для эксплуатационного пилота.
5. Выполнить общую приёмку всех 14 сервисов: воспроизводимый HTTP E2E, реальные данные, отказы зависимостей, перезапуски, offline и формальный полевой pass/fail.

Приоритеты: P0 — первый полевой MVP, P1 — эксплуатационный пилот. Календарные сроки и исполнители не назначены. Для закрытия каждого тикета требуются PR/commit, команды и результаты проверок и версии данных/конфигурации. Аппаратные проверки не заменяются симулятором.
