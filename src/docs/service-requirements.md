# Требования к сервисам SmartMetrix

Версия 1, 30.09.2026. Требования описывают целевое поведение; наличие кода или
теста не означает приёмку. Численные допуски полевых измерений утверждаются до
испытаний. Этот документ дополняет контракты API в `docs` и план завершения сервисов.

## Правила проверки

У каждого требования постоянный ID. Автоматические проверки находятся в
`tests/SmartMetrix.ArchitectureTests`; имена ниже указывают классы тестов.
«Есть тесты» означает наличие проверок части сценариев, а не полное покрытие
требования. «Разрыв» — отсутствующая интеграция или доказательство приёмки.
Для закрытия требования нужны результат прогона, версия кода, конфигурация и данные.
Процент покрытия строк и ветвей измеряется отдельно от покрытия требований.

## Общие требования

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|
| SYS-01 | Каждый сервис предоставляет `/health`, `/ready`, `/info`; readiness отражает недоступность обязательных зависимостей. | ServiceDefaultsTests, PipelineHttpIntegrationTests; требуется проверка всех HTTP-хостов. |
| SYS-02 | Ошибочный запрос не создаёт успешный результат; ошибки имеют диагностируемый код, журнал содержит correlation/measurement ID, секреты не выходят в ответ. | ServiceDefaultsTests, OperatorApiIntegrationTests, RtspCameraTests. |
| SYS-03 | Контракты имеют версию; большие артефакты передаются по URI с checksum; несовместимая схема отвергается. | ContractTests. |
| SYS-04 | Отмена, таймаут, повтор команды и перезапуск не создают второй подтверждённый результат. | MeasurementStateMachineTests, PipelineHttpIntegrationTests, CloudSyncTests; разрыв: полный цикл через брокер. |
| SYS-05 | Симулятор включается явно; отсутствие аппаратного backend не заменяется синтетическим измерением. | CameraCaptureTests, DepthReconstructionTests, StoneVisionTests. |
| SYS-06 | Сохраняемые реестры, очереди и результаты переживают перезапуск и восстановление из backup. | PostgreSQL persistence и PostgresPersistenceTests реализованы; режим без PostgreSQL не даёт долговечности реестров. Полный restore из backup требует отдельной приёмки. |

## TriggerService

Вход: показания движения, вибрации, дистанции, готовность камер и ручная команда.
Выход: решение с причиной и событие CaptureRequested; владеет debounce/cooldown.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|
| TRG-01 | Захват запрещён при движении, превышении вибрации, неготовых камерах, inhibit, нечисловых показаниях или отрицательном RMS. Ручная команда не обходит запреты. | TriggerDecisionTests. |
| TRG-02 | Без команды захвата нет; безопасное состояние выдерживается весь debounce; нарушение сбрасывает отсчёт; повтор подавляется до конца cooldown. | TriggerDecisionTests. |
| TRG-03 | Принятое решение публикует событие с уникальным ID измерения, причиной и исходными показаниями. Повтор доставки запускает одно измерение. | TriggerDecisionTests, ContractTests; разрыв: Trigger → Orchestrator. |

## MeasurementOrchestrator

Вход: запуск, cancel/retry и результаты этапов. Выход: состояние и итоговый JSON.
Владеет журналом переходов, версиями команд и checkpoint.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|
| ORC-01 | Только допустимые переходы состояния; Completed терминален; commandId идемпотентен; несовпадающая expectedVersion отклоняется. | MeasurementStateMachineTests, PipelineHttpIntegrationTests. |
| ORC-02 | Этапы выполняются в установленном порядке; отклонённое качество не допускает реконструкции; ссылки и provenance доходят до итогового результата. | PipelineHttpIntegrationTests. |
| ORC-03 | После restart используются checkpoint; число повторов ограничено; cancel не отменяется поздним ответом зависимости. | PipelineHttpIntegrationTests. |
| ORC-04 | Completed надёжно ставится в CloudSync без зависимости успеха измерения от доступности облака. | CloudDispatchTests: импорт артефактов, потеря подтверждения и restart без дублей; целевой облачный приёмник требует отдельной приёмки. |

## CameraService

Вход: measurementId и calibrationId. Выход: ссылки на кадры A/B/C, checksum,
метки времени и происхождение; оригиналы принадлежат StorageService.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|
| CAM-01 | Принимается ровно один непустой кадр A/B/C. Неполный набор и превышение бюджета аппаратного рассогласования отклоняются до записи в Storage. | CameraCaptureTests, CameraRequirementsTests, RtspCameraTests; бюджет задаётся MaximumTimestampSkewNanoseconds. |
| CAM-02 | Успех возвращается после сохранения всех кадров; ошибка хранилища не превращается в успешный захват. | CameraRequirementsTests, PipelineHttpIntegrationTests. |
| CAM-03 | Повтор capture использует сохранённую квитанцию; RTSP и Simulator явно помечены тестовыми; host timestamp не выдаётся за hardware timestamp. | RtspCameraTests; разрыв: отдельная проверка квитанции после restart. |
| CAM-04 | Arena без настройки выдаёт NotConfigured; на оборудовании подтверждены синхронизация, экспозиция и серийные номера. | CameraCaptureTests; аппаратная приёмка отдельно. |

## CalibrationService

Вход: intrinsics/extrinsics, карты ректификации и интервалы действия.
Выход: версионированный bundle; владеет активацией, отзывом и аудитом.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|
| CAL-01 | Геометрия A/B/C, матрицы и ошибка репроекции валидируются; недопустимая ошибка блокирует активацию. | CalibrationRegistryTests. |
| CAL-02 | Для установки и времени существует не более одной активной версии; отозванная версия не активируется повторно. | CalibrationRegistryTests. |
| CAL-03 | Bundle имеет schema/version/checksum; изменение содержимого обнаруживается; отзыв фиксирует автора и причину. | CalibrationRegistryTests. |
| CAL-04 | Реальная калибровка и карты воспроизводимо загружаются после перезапуска. | RectificationTests для карт; разрыв: сохранение реестра и аппаратный набор. |

## QualityService

Вход: набор кадров и пороги. Выход: решение, метрики и причины отбраковки.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|
| QUA-01 | Отсутствие, дубликат камеры и несогласованные timestamps приводят к отказу с машинно читаемой причиной. | QualityAnalyzerTests. |
| QUA-02 | Метрики детерминированы и нормализованы; некачественный набор останавливает конвейер. | QualityAnalyzerTests, PipelineHttpIntegrationTests. |
| QUA-03 | Версия порогов сохраняется; ложный допуск/отказ измеряется на отложенной разметке смаза, пыли, света и текстуры. | Разрыв: утверждённые допуски и полевой набор. |

## DepthService

Вход: кадры и калибровка. Выход: depth/confidence/invalid и организованное 3D-облако.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|
| DEP-01 | Карты ректификации проверяются по checksum, форме и камере; повреждённая карта не создаёт геометрию. | RectificationTests. |
| DEP-02 | AB/AC/BC приводятся в общую сетку A; окклюзии и invalid disparity не создают валидных точек; объединение учитывает confidence. | DepthReconstructionTests, RectificationTests; полное включение BC в рабочем конвейере проверяется отдельно. |
| DEP-03 | Сохраняются версии калибровки, координатная система, checksum и согласованность размеров карт. Native без библиотеки выдаёт явную ошибку. | DepthReconstructionTests, PipelineHttpIntegrationTests. |
| DEP-04 | На сценах 12/20/30 м соблюдаются заранее согласованные точность, полнота и время. | Разрыв: эталоны и прогон CPU/GPU на целевой машине. |

## SegmentationService

Вход: RGB8 и параметры детекции. Выход: mask/confidence/instanceMap и provenance.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|
| SEG-01 | Размеры, формат и параметры проверяются до инференса; некорректные RLE/формы ответа отвергаются до записи артефактов. | SegmentationGoldenTests, StoneVisionTests. |
| SEG-02 | Перекрытие масок разрешается по confidence с детерминированным tie-break; исходные instance ID и ответ сохраняются. | StoneVisionTests, PipelineHttpIntegrationTests. |
| SEG-03 | Readiness требует загруженных моделей; HTTP-ошибка не переключает на симулятор; пустая детекция не выдумывает камни. | StoneVisionTests. |
| SEG-04 | Качество и время подтверждаются на реальных весах; StoneVision не заявляет распознавание трещин. | Разрыв: полевой набор и GPU-прогон; ограничения в stonevision.md. |

## BlockAnalysisService

Вход: 3D и маски в одной пиксельной сетке. Выход: блоки, размеры, D50/D80.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|
| BLK-01 | Несовместимые размеры и некорректные labels отвергаются; соприкасающиеся разные instance ID не сливаются. | BlockAnalysisTests. |
| BLK-02 | Размеры имеют явные единицы; процентили используют документированное объёмное взвешивание; provenance сохраняется. | BlockAnalysisTests, PipelineHttpIntegrationTests. |
| BLK-03 | Пограничные/неполные блоки и низкая уверенность отмечаются; точность размеров проверяется относительно ручного эталона. | BlockAnalysisTests для синтетики; разрыв: полевой эталон. |

## LocalPositioningService

Вход: отсчёты приборов и versioned transforms. Выход: поза на hardware timestamp,
источники и covariance; live-буфер не заменяет архив результата.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|
| POS-01 | Поза интерполируется на время экспозиции; отсутствие обрамляющих отсчётов и противоречащие источники отвергаются. | LocalPositioningTests. |
| POS-02 | Преобразования сохраняют версии, источники и неопределённость; результат выражен в локальной системе. | LocalPositioningTests, ContractTests. |
| POS-03 | Буфер ограничен, отсортирован по hardware timestamp и разделён по установкам; реальные драйверы подтверждены replay-набором. | PositioningBufferRequirementsTests для буфера; разрыв: аппаратные адаптеры. |

## ControlPointService

Вход: реперы, изменения, CSV/GeoJSON. Выход: версии координат, история и аудит.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|
| CPT-01 | Изменение создаёт новую версию; неактивный репер нельзя использовать; использованный нельзя удалить. | ControlPointRegistryTests. |
| CPT-02 | Импорт диагностирует ошибочные строки; экспорт/импорт сохраняет координаты, единицы, точность и дату. | ControlPointRegistryTests. |
| CPT-03 | Backup/restore сохраняет версии, аудит и ссылки использования. | Разрыв: долговременное хранение и восстановление реестра. |

## GeoreferenceService

Вход: геометрия, цепочка преобразований и поза экспозиции. Выход: геометрия карьера.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|

| GEO-02 | Преобразование и обратный проход сохраняют геометрию в пределах допуска; версии каждого шага присутствуют в результате. | GeoreferenceTests. |
| GEO-03 | Ошибки положения и угла увеличивают оценку неопределённости; точность подтверждается контрольными реперами. | GeoreferenceTests для синтетики; разрыв: геодезическая приёмка. |

## StorageService

Вход: артефакт, measurementId, путь и ожидаемый checksum. Выход: неизменяемая ссылка.

| ID | Требование и критерий приёмки | Проверка |
| STO-01 | Повтор одинакового содержимого идемпотентен; отличающееся содержимое по тому же ключу отклоняется. | StorageServiceIntegrationTests; требуется реальный MinIO. |
| STO-02 | Checksum проверяется при загрузке и чтении; повреждённый объект не выдаётся как валидный. | StorageServiceIntegrationTests; требуется реальный MinIO. |
| STO-03 | Недопустимые пути и пустой measurementId отвергаются; временные загрузки очищаются; срок presigned URL ограничен. | StorageRequirementsTests для путей; разрыв: пустой measurementId и эксплуатационная проверка lifecycle. |
| STO-04 | Backup/restore возвращает оригиналы и метаданные с теми же checksum. | Разрыв: эксплуатационный прогон. |

## CloudSyncService

Вход: подтверждённый результат с версией и артефактами. Выход: облачное подтверждение,
статус и аудит; владеет долговременной очередью и spool.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|
| SYN-01 | Повтор measurementId/version создаёт одну запись; исходные файлы копируются в spool; результаты приоритетнее кадров. | CloudSyncTests. |
| SYN-02 | После restart продолжается неподтверждённый остаток; каждый chunk передаётся с checksum. | CloudSyncTests. |
| SYN-03 | Offline вызывает retry/backoff; конфликт версии не повторяется автоматически; spool удаляется только после подтверждения. | CloudSyncTests проверяет терминальные состояния; разрыв: тесты worker и отказов облака. |
| SYN-04 | Ошибка постановки не делает последующий повтор невозможным и не создаёт частично принятую запись. | CloudSyncTests.FailedEnqueueCanBeRetriedAfterMissingArtifactArrives; исправлено повторное копирование неопубликованного spool. |

Вход: запрос оператора/инженера/администратора. Выход: состояние, команды и аудит.

| ID | Требование и критерий приёмки | Проверка |
|---|---|---|

| API-02 | Ненастроенная зависимость даёт NotConfigured, недоступная — Degraded; адреса и секреты не раскрываются. | OperatorApiIntegrationTests. |

| API-04 | Отключённая или заблокированная учётная запись не входит; сброс пароля снимает блокировку; реестр переживает restart; список пользователей не содержит salt/hash/пароль. | UserAccountRequirementsTests. |

## Границы полного покрытия

Помимо 14 сервисов проверяются BuildingBlocks (контракты, messaging, telemetry),
HTTP-конвейер, E2ESimulator, Python-калибровка и RTK-станция. Native C++, браузерный
JavaScript, deployment-скрипты и StoneVision submodule требуют своих прогонов;
отчёт .NET не измеряет их покрытие. Аппаратные и полевые требования нельзя закрыть
прохождением симулятора. Неутверждённые допуски не заменяются произвольными числами.
