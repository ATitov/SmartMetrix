# GUI SmartMetrix — формальные требования, версия 1

## Границы поставки

Пять АРМ реализуются в одном веб-приложении. [Интерактивные макеты](gui-prototype/index.html) показывают целевое поведение на синтетических данных и не управляют оборудованием. Рабочие панели `/operator/` и `/engineer/` остаются отдельной существующей реализацией. Требования ниже относятся к целевой системе, а не подтверждают готовность всех функций.

## Источники и направления данных

Таблица ниже фиксирует исходные разрывы на момент проектирования GUI. Актуальный реализованный контракт и оставшиеся ограничения: [API АРМ v1](workstation-api.md). В частности, v1 уже поддерживает пять ролей, совмещение, scope и реестр проверок; интерактивные макеты остаются автономными.

Браузер → ApiGateway → профильный сервис → хранилище. Только Gateway аутентифицирует пользовательские команды и предоставляет разрешённые данные браузеру. Прямой доступ браузера к NATS, БД, внутренним портам, секретам и произвольным URI артефактов запрещён. Тяжёлые артефакты выдаются через авторизованный маршрут или ограниченную по времени и объекту ссылку. Авторизация проверяет площадку, комплекс и версию результата.

| ID / АРМ | Объекты и экран | Источник истины | Доступный интерфейс | Доработка Gateway / результат действия |
|---|---|---|---|---|
| GUI-OP-01 / оператор | Готовность, активное измерение | TriggerService, CameraService, Orchestrator; readiness сервисов | `GET /api/operator/status` агрегирует readiness, но не все условия запуска | Добавить причины блокировки и время наблюдения каждого условия |
| GUI-OP-02 / оператор | Кадры A/B/C, качество | CameraService, QualityService, StorageService | Сервисные capture/quality и хранилище; публичного предпросмотра нет | Авторизованный preview; хранить время кадра, признак тестовой камеры; не выдавать внутренний URI |
| GUI-OP-03 / оператор | Запуск и журнал измерений | MeasurementOrchestrator | `GET/POST /api/operator/measurements`, `GET /api/operator/measurements/{id}`, `/stages/{stage}` | Запуск с commandId; подтверждённый ответ содержит measurementId; фильтры по площадке, времени и комплексу требуют расширения |
| GUI-GEO-01 / геолог | Снимок, блоки, трещины, D10–D90 | BlockAnalysisService, SegmentationService, DepthService, StorageService | Артефакты этапов; единой публичной модели результата нет | Агрегат результата с единицами, качеством, областями и версиями |
| GUI-GEO-02 / геолог | Проверка, комментарии и отчёты | Требуемый реестр проверок и сервис отчётов | Отсутствует | Подтверждение конкретной версии с actor/time/comment; экспорт фиксирует версии и область анализа |
| GUI-SRV-01 / маркшейдер | Карта, точки, СК | ControlPointService, LocalPositioningService | Внутренние `/control-points`, `/api/transforms`, `/api/poses/{excavatorId}` | Прокси с правами, каталог СК, карта измерений, версии и невязки |
| GUI-SRV-02 / маркшейдер | Импорт, проверка и перепривязка | ControlPointService, GeoreferenceService | Внутренние `/control-points/import/csv`, `/import/geojson`, `/export/csv`, `/export/geojson`; georeference этап | Предпросмотр и атомарное применение импорта; отдельная команда перепривязки с новой версией результата |
| GUI-ENG-01 / инженер | Ресурсы, логи, конфигурация | EngineeringTools, readiness сервисов, журналы | `/api/operator/engineering/system`, `/logs`, `/config`; `/api/operator/audit` | Ограничить конфигурацию allowlist, маскировать секреты, фильтровать область доступа |
| GUI-ENG-02 / инженер | Камеры, калибровки, модели | CameraService, CalibrationService, SegmentationService, DepthService | Внутренние API калибровок и segmentation capabilities | Веб-мастер калибровки, публикация версий и управляемая активация |
| GUI-ENG-03 / инженер | Отмена, повтор, сравнение | MeasurementOrchestrator | `POST /api/operator/measurements/{id}/cancel` и `/retry` | Передавать commandId, expectedVersion, reason, confirmed; 409 не повторять автоматически |
| GUI-ADM-01 / администратор | Пользователи, роли, области доступа | UserAccountStore | `/api/admin/users`, `/{username}/enabled/{enabled}`, `/{username}/password` | Сейчас одна роль и три типа ролей; добавить геолога, маркшейдера, совмещение и области доступа |
| GUI-ADM-02 / администратор | Диски, резервные копии, синхронизация | StorageService, CloudSyncService, deployment backup tooling | Полного публичного API нет | Каталог копий, проверки восстановления, политики и агрегат очереди; команда передачи не означает доставку |

Адреса в колонке «Доработка» намеренно не выдаются за реализованные API. Внутренние сервисные маршруты нельзя вызывать из GUI напрямую.

## Роли и ограничения

Целевая матрица действий приведена в [web-gui.md](web-gui.md). Идентификаторы ролей для будущего контракта: operator, geologist, surveyor, engineer, administrator. Права складываются при совмещении, ограничения области данных сохраняются. Переключатель АРМ в макете предназначен только для просмотра дизайна.

GUI-SEC-01: сервер возвращает 401 без сессии, 403 при недостатке прав; чужой объект не раскрывает данные. Скрытие кнопки не заменяет проверку API.

GUI-SEC-02: cookie-команды защищены от CSRF; журнал не содержит паролей, ключей и полных подписанных URL. Все изменения записывают actor, timestamp, action, target, before/after version, reason, success, correlationId.

GUI-SEC-03: текущий Gateway разрешает администратору операторские и инженерные команды, хранит одну роль, не обеспечивает требуемую объектную область доступа. Это известные разрывы относительно целевой матрицы; макеты их не исправляют и не подтверждают безопасность production.

## Единый промышленный стандарт SMX-UI-1

Это внутренний стандарт проекта, без заявления о сертификации по ISA/ГОСТ. Основа — существующая палитра SmartMetrix. Цель доступности: [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/); полная оценка соответствия выполняется отдельно.

| ID | Проверяемое правило |
|---|---|
| GUI-DS-01 | Общие токены: фон #081113, панель #101d1f, текст #eef7f5, вторичный текст #a9bdb9, акцент #67e8b5. Одна типографика Segoe UI/system-ui, базовый текст 16px, линия 1.5, сетка отступов 4/8/12/16/24/32px |
| GUI-DS-02 | Цвет обозначает состояние и сопровождается текстом: готово, предупреждение, отказ, нет данных. Не использовать декоративную тревожную индикацию. Контраст текста ≥4.5:1, крупного текста ≥3:1; доступность графики и границ оценивается отдельно |
| GUI-DS-03 | Все основные кнопки и поля не меньше 44×44 CSS px — внутренний порог проекта. Видимый focus, логичный Tab, ссылки с назначением, label у полей, Escape закрывает диалог и возвращает фокус |
| GUI-DS-04 | Постоянно видны площадка, комплекс и режим данных. Заголовок отражает АРМ. Макет всегда помечен «Демонстрационные данные» |
| GUI-DS-05 | Числа содержат единицы; время содержит часовой пояс; отсутствующее значение — «Нет данных», не 0. Статусы обработки, проверки и синхронизации показываются отдельно |
| GUI-DS-06 | Команда открывает диалог с объектом, последствиями и причиной; повторный submit блокируется. Ошибка сохраняет введённые данные. Критические команды требуют серверной проверки версии |

| GUI-RWD-02 | 768–1199 CSS px, планшет | Две колонки там, где помещается содержимое; навигация сверху, перенос панелей |

| GUI-STATE-01 | Загрузка | Текст ожидания и блокировка команды; не показывать старые данные как новые |
| GUI-STATE-02 | Пусто / ошибка | Объяснение, отсутствие вымышленных результатов; отдельный путь повторного чтения |
| GUI-STATE-03 | Нет связи с сервером | Старые данные помечены, команды запрещены, автоматическая отправка накопленных команд запрещена |
| GUI-STATE-04 | Нет интернета, локальный сервер доступен | Локальные сценарии работают; облачная очередь остаётся отдельным состоянием |
| GUI-STATE-05 | Частичные данные | Доступные результаты сохраняются, отсутствующая часть названа явно |

Целевое обновление readiness — каждые 5 секунд, признак устаревания после 15 секунд без подтверждения. Это UI-параметры, не метрологические пороги. Даты и давность рассчитываются по меткам сервера. Крупные артефакты загружаются лениво; запрос отменяется при уходе со страницы.

## Макеты и сценарии

Общая композиция: навигация → контекст объекта и режим → заголовок и основное действие → показатели → рабочая область → список объектов → происхождение данных. На телефоне порядок сохраняется. Общая карточка измерения открывается из списка.

| АРМ | Рабочая область макета | Основное действие в демонстрации |
|---|---|---|
| Оператор | Три камеры, условия запуска, очередь смены | Запустить измерение → диалог → запись демонстрационного действия |
| Геолог | Схема сегментации, фракции, проверка результатов | Подтвердить выбранную версию → причина → статус проверки |
| Маркшейдер | Схема карты, точки, система координат и невязки | Проверить привязку → комментарий → журнал |
| Инженер | Состояние сервисов, калибровка и этапы обработки | Повторить обработку → причина → новая демонстрационная попытка |
| Администратор | Пользователи, роли, хранение и очередь | Проверить резервную копию → журнал демонстрационного действия |

Схемы камер, карты и сегментации — векторные заглушки с подписью, не реальные снимки и не результат реконструкции. Полноценное 3D, реальный импорт, восстановление и управление пользователями требуют реализации backend и последующих экранов.

## Проверки и трассируемость

Автоматические тесты макетов: `tools/gui-tests`. Запуск и точные границы покрытия описаны в его README. Автоматизация проверяет все пять АРМ, размеры экранов, состояния, переходы, диалог, валидацию, запрет команд без данных, отсутствие внешних запросов, XSS в комментарии, семантику и базовый контраст токенов.

| Требования | Проверка макета | Дополнительная приёмка production |
|---|---|---|
| OP/GEO/SRV/ENG/ADM | Пять различных экранов и действие каждого, источник данных | Контрактные тесты Gateway с реальными DTO и ошибками сервисов |
| DS-01…06 | Общие CSS, контраст, поля, клавиатура, диалог | Screen reader, экспертный аудит графики и всех рабочих форм |
| RWD-01…04 | 320, 390, 768, 1024, 1440px, снимки экранов | Физические Android/iOS-планшеты и телефоны, масштаб текста 200%, полевые условия |
| STATE-01…05 | Переключение loading/empty/error/offline/partial/ready | Реальный обрыв сети, reconnect, отмена запросов, устаревание по времени |
| SEC-01…03 | Макет не посылает команды и экранирует комментарии | 401/403, CSRF, объектная изоляция, совмещение ролей, аудит — обязательные интеграционные тесты перед вводом |
| Версии и подтверждения | Отдельные статусы и причина действия | Конкурентные команды: 409, idempotency, подтверждение точной версии, сохранение прежних результатов |

Прохождение тестов макетов не означает прохождение production-приёмки. Существующие .NET-тесты проверяют текущую систему; новые серверные требования должны получить тесты вместе с реализацией соответствующих API.
