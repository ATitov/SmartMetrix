# API пяти АРМ — контракт v1

Реализация: ASP.NET Core / .NET 10, существующий `SmartMetrix.ApiGateway`.
Обновлено 04.10.2026. Это серверный API, независимый от телефона, планшета и ПК.
Операторская и инженерная панели подключены к scoped API; макеты остальных АРМ
требуют дальнейшей интеграции. JSON использует camelCase, даты — ISO 8601 с UTC offset.
Базовый адрес: `/api/v1`. Дополнительные scoped-маршруты сменных отчётов и
настройка `ExcavationReports:Roots` описаны в [excavator-replay.md](excavator-replay.md).

## Область версии

Версия 1 предоставляет рабочие серверные маршруты для всех пяти ролей: чтение состояния и измерений, команды оркестратора, проверка геолога и JSON-отчёт, опорные точки и преобразования координат, черновики калибровок, возможности сегментации, пользователи, аудит, состояние синхронизации и проверка файлов резервных копий.

Проектирование GUI шире этой версии API. Поток кадров/3D, редактирование областей анализа, атомарный массовый импорт, активация калибровки с блокировкой измерительного конвейера, управление моделями, перепривязка завершённых результатов, создание/восстановление резервной копии и передача подтверждённого результата в облако требуют отдельных сервисных операций. Они **не подменяются успешными заглушками**. Текущие внутренние импорт и калибровка не дают всех необходимых гарантий конкурентности и сохранности после перезапуска.

## Требования к общему контракту

| ID | Требование и поведение реализации |
|---|---|
| ARM-SEC-01 | Каждый маршрут v1 требует cookie-сессию или действительный API-ключ. Нет аутентификации → 401; нет роли/области → 403 |
| ARM-SEC-02 | Пять ролей: operator, geologist, surveyor, engineer, administrator. Совмещение через additionalRoles. Администратор не наследует профессиональные команды |
| ARM-SEC-03 | `scopeId` связывает площадку, комплекс, rig и СК. Он назначается пользователю явно. ID измерения проверяется по excavatorId и coordinateSystemId; чужой объект → 404. URI сервисов выбираются только серверной конфигурацией |
| ARM-SEC-04 | Cookie-команды требуют `X-CSRF-Token`, полученный через `/api/auth/csrf`. Для API-ключа токен не требуется. Все v1-ответы имеют Cache-Control: no-store |
| ARM-SEC-05 | Публичный DTO измерения не содержит processedCommands, внутренних URI артефактов и диагностических адресов. Метаданные этапов очищаются от полей URI/URL/path/secret/password/token. Ответы ошибок зависимостей не передают их тексты |
| ARM-OP-01 | Запуск: только operator/engineer, обязательные commandId и measurementId. Идентификаторы комплекса и СК подставляет сервер |
| ARM-OP-02 | Readiness не означает проверку остановки/вибрации: `canStart:null`, `triggerConditionsChecked:false`. Отсутствующая зависимость — NotConfigured, никаких фиктивных показателей |
| ARM-GEO-01 | Проверка относится к expectedVersion и Completed. Идемпотентное повторение возвращает прежнюю запись; тот же commandId с другим телом/автором → 409. Решение сохраняется атомарной заменой файла |
| ARM-SRV-01 | Точки фильтруются по СК области; создание точки/преобразования с чужими идентификаторами → 400. История и список преобразований также фильтруются |
| ARM-ENG-01 | cancel/retry только engineer, с confirmed:true, reason и expectedVersion. Разрешённость перехода и идемпотентность проверяет оркестратор |
| ARM-ADM-01 | Пользователи и назначения доступны глобальному администратору. Список не возвращает соль, хеш или пароль. Изменение ролей/областей и отключение учитываются при следующем запросе cookie-сессии |
| ARM-ADM-02 | Проверка копии вычисляет SHA-256 реального файла и сравнивает с sidecar. Проверка хеша не означает проверку восстановления |
| ARM-ERR-01 | Ошибки upstream 400/404/409/422 сохраняют HTTP-статус, остальные → 502. Тексты внутренних ошибок не раскрываются |
| ARM-ERR-02 | Таймаут HTTP-зависимости → 504. Отмена браузером передаётся вниз. Общий timeout включает чтение тела ответа |
| ARM-ERR-03 | Не задан URL сервиса → 503 NotConfigured. Невалидный JSON зависимости → 502 InvalidDependencyResponse. Ответ JSON ограничен 8 МиБ, входящий v1 body — 1 МиБ |

`scopeId`, siteId, excavatorId, rigId, coordinateSystemId и ID резервной копии: ASCII буквы/цифры, `_`, `-`, `.`, от 1 до 64 символов; первый символ — буква/цифра. Эти ограничения исключают ввод путей в маршруты сервисов. Конфигурация сервисов — доверенная эксплуатационная настройка, недоступная через тело пользовательского запроса. HTTP redirects отключены.

## Каталог маршрутов

В таблице `S` означает `/api/v1/scopes/{scopeId}`. Любая операция с `S` требует назначенную область в дополнение к роли. Чтение общих измерений доступно всем пяти ролям.

| Метод и маршрут | Роль | Объект / источник / результат |
|---|---|---|
| GET `/api/v1/workstations` | Любая аутентифицированная | Доступные роли и области без адресов сервисов |
| GET `S/operator/status` | Все пять | Readiness configured-сервисов; проверка времени отдельно для каждого |
| GET `S/measurements?limit=50&status=Completed` | Все пять | Оркестратор; фильтр принадлежности и DTO, limit 1…200 |
| POST `S/measurements` | operator, engineer | Создание измерения в Orchestrator, 201 + Location |
| GET `S/measurements/{id}` | Все пять | DTO измерения + решение по текущей версии; synchronization=Unknown до подключения объектного статуса очереди |
| GET `S/measurements/{id}/stages/{stage}` | Все пять | Сохранённые метаданные этапа через Orchestrator, без прямого URL артефакта |
| GET `S/geologist/measurements/{id}/reviews` | geologist | История проверок, WorkstationReviewStore |
| POST `S/geologist/measurements/{id}/reviews` | geologist | Approved / NeedsRevision, 200, сохранённый автор и серверное время |
| GET `S/geologist/measurements/{id}/report` | geologist | JSON-отчёт schemaVersion=1, значения и проверка точной версии |
| GET `S/surveyor/control-points` | surveyor | ControlPointService, точки текущей СК |
| POST `S/surveyor/control-points` | surveyor | Создание по контракту CreateControlPointRequest, actor берётся из сессии |
| GET `S/surveyor/control-points/{pointId}/history` | surveyor | Версии принадлежащей области точки |
| GET `S/surveyor/transforms` | surveyor | LocalPositioningService, версии преобразований комплекса/СК |
| POST `S/surveyor/transforms` | surveyor | Новая версия TransformDefinition, дубли отклоняет сервис |
| POST `S/engineer/measurements/{id}/cancel` | engineer | Допустимая отмена по состоянию оркестратора |
| POST `S/engineer/measurements/{id}/retry` | engineer | Повтор Failed/Rejected; Completed не переобрабатывается существующей машиной состояний |
| GET `S/engineer/calibrations` | engineer | CalibrationService, фильтр rigId |
| POST `S/engineer/calibrations` | engineer | Черновик CalibrationPayload; rigId обязан совпадать с областью |
| GET `S/engineer/segmentation/capabilities` | engineer | Поддерживаемые возможности SegmentationService |
| GET `/api/v1/engineer/system` | engineer | Диагностика хоста самого Gateway через EngineeringTools, не удалённого комплекса |
| GET `S/administrator/sync/status` | administrator | Агрегат очереди CloudSyncService: очередь должна принадлежать указанному развёртыванию |
| GET `S/administrator/audit` | administrator | Записи локального аудита, отфильтрованные по scopeId |
| GET `/api/v1/administrator/users/` | administrator | Глобальный реестр пользователей экземпляра Gateway |
| POST `/api/v1/administrator/users/` | administrator | CreateUserRequest, 201; повтор логина → 409 |
| PUT `/api/v1/administrator/users/{username}/access` | administrator | Замена основной роли, дополнительных ролей и областей, 204 |
| PUT `/api/v1/administrator/users/{username}/enabled/{enabled}` | administrator | Отключение/включение, 204; самоблокировка через v1 запрещена |
| PUT `/api/v1/administrator/users/{username}/password` | administrator | Сброс пароля, минимум 12 символов, 204 |
| GET `/api/v1/administrator/backups/` | administrator | До 100 zip-файлов из настроенного локального каталога, без полных путей |
| POST `/api/v1/administrator/backups/{id}/verify` | administrator | Проверка `{id}.zip` по `{id}.zip.sha256`; 200 с verified true/false |

Глобальные административные маршруты управляют экземпляром Gateway, а не отдельной площадкой. Для разных организаций нужны отдельные экземпляры либо последующая модель tenant administrator.

## Тела команд и ответы

Запуск измерения — `POST S/measurements`:

```json
{
  "commandId": "11111111-1111-4111-8111-111111111111",
  "measurementId": "22222222-2222-4222-8222-222222222222",
  "reason": "Измерение участка 04"
}
```

Повтор/отмена — `POST S/engineer/measurements/{id}/retry`:

```json
{
  "commandId": "33333333-3333-4333-8333-333333333333",
  "expectedVersion": 8,
  "reason": "Повтор после устранения ошибки",
  "confirmed": true
}
```

Проверка — `POST S/geologist/measurements/{id}/reviews`:

```json
{
  "commandId": "44444444-4444-4444-8444-444444444444",
  "expectedVersion": 12,
  "decision": "Approved",
  "reason": "Качество и контуры проверены"
}
```

Для этих команд GUID не может быть пустым; version ≥0; reason содержит 3…500 непробельных после trim символов. Повтор транспортного запроса использует прежний commandId, не новый. Создание точки, преобразования и черновика калибровки имеет семантику соответствующего сервиса, не универсальную commandId-идемпотентность.

Назначение доступа — `PUT /api/v1/administrator/users/ivan/access`:

```json
{
  "role": "operator",
  "additionalRoles": ["surveyor"],
  "scopeIds": ["north-smx03"]
}
```

Области должны существовать в конфигурации; wildcard не поддерживается. Переключение АРМ в браузере не меняет серверные claims. В API-ключе пока одна роль, области задаются отдельной конфигурацией. Идентификатор ключа в аудите — фрагмент SHA-256, а не часть секрета.

Даты результатов берутся из Orchestrator, время проверки/отчёта — с Gateway. Значения D10–D95 передаются без пересчёта из существующего контракта анализа (мм), confidence/coverage/oversizeFraction — доли, blockCount — количество. `null` не заменяется нулём. Статусы обработки, проверки и передачи независимы.

Допустимые stage: calibration, capture, pose, quality, depth, segmentation, analysis, georeference, result. Неизвестный stage → 400. Неизвестная инженерная команда → 404.

Ошибки представлены Problem Details; контролируемые ошибки v1 содержат `code` и `traceId`. Ошибки авторизации могут иметь пустое тело, стандартные ошибки привязки ASP.NET Core — стандартное Problem Details. Клиент в первую очередь проверяет HTTP status. Не следует автоматически повторять 409.

## Конфигурация и миграция

Шаблон без секретов: [workstation-api.example.json](workstation-api.example.json). Он не загружается автоматически. Секция `Workstations` переносится в конфигурацию конкретного развёртывания. Адреса заменяются реальными адресами доступных Gateway сервисов.

1. Сохранить резервную копию users.json и конфигурации.
2. Определить Scopes с неизменяемыми идентификаторами площадок/комплексов/СК и настроить URL сервисов.
3. Через глобального администратора создать пользователей либо назначить им роли и scopeIds. Старые учётные записи читаются без миграции файла; отсутствие scopeIds означает отсутствие доступа к v1-областям.
4. Cookie-клиент получает `/api/auth/csrf` после входа и передаёт token в `X-CSRF-Token` для POST/PUT/DELETE. Существующий JS-клиент обновлён для этого протокола.
5. При непустом Workstations:Scopes старый `/api/operator/*` отвечает 410 UseScopedWorkstationApi, чтобы не обходить ограничения областей. Старые рабочие панели нужно перевести на v1 перед включением Scopes в эксплуатации. По умолчанию список пуст, автоматического переключения действующего развёртывания нет.

Старые `/api/admin/*` остаются интерфейсом глобального администратора. Браузерные сессии перечитывают роли/области из реестра на каждом запросе. Сброс пароля сам по себе не отзывает уже выданную cookie; для немедленного прекращения сессий отключить пользователя. Новый контракт отзывов сессий потребует security stamp.

## Хранение и эксплуатационные границы

- ReviewPath: атомарный JSON-файл, сериализация операций внутри одного процесса. Запись ReviewRecord является аудитом профессионального решения. Это не распределённое хранилище; несколько Gateway не должны совместно писать в один файл.
- Остальные успешные изменяющие команды пишут в существующий JSONL-аудит с scopeId и correlationId. Аудит и внешняя операция не являются общей транзакцией; при сбое записи аудита после upstream-успеха клиент должен проверить состояние и повторять только с прежним commandId там, где он поддерживается. Полный журнал отказов и транзакционный outbox остаются эксплуатационным расширением.
- Список измерений — окно последних 200 записей upstream, затем фильтрация и limit; это не пагинируемый архив. Для полного архива нужно расширить IMeasurementStore/PostgreSQL.
- `Completed` сейчас терминален и неизменяем в Orchestrator. Поэтому подтверждение фиксируется для стабильной версии. Если появится редактирование завершённого результата, нужна транзакционная проверка версии в сервисе-владельце.
- Проверка backup отклоняет reparse points и принимает только файл из настроенного каталога. Каталог и sidecar должны быть доступны на запись только доверенному процессу резервирования. Сам SHA-256 не проверяет ZIP-структуру, согласованность БД или возможность восстановления.
- CalibrationRegistry, ControlPointRegistry и TransformRegistry сохраняют свою текущую модель хранения; эти API не превращают их в постоянную промышленную БД.
- Внутренние сервисы должны быть закрыты от браузеров и недоверенной сети. Наличие Gateway не добавляет аутентификацию на их внутренние порты автоматически.

## Проверки

`WorkstationApiTests`: настоящий HTTP-host ASP.NET Core с API-key/cookie authentication, реальным реестром пользователей, review store и backup-файлами; upstream подменён детерминированным HttpMessageHandler. Проверяет 401/403, пять ролей, scope и IDOR, запрет legacy обхода, CSRF, команды, проверки версий, воспроизводимость после переоткрытия, разделение СК, checksum и отсутствие секретов в DTO.

`WorkstationBackendTests`: преобразование ошибок, timeout/cancellation, отсутствующие зависимости, повреждённый JSON и публичная проекция. Тесты входят в существующий `dotnet test SmartMetrix.sln`; нового тестового runtime для API не требуется.

Реальные камеры, PostgreSQL, NATS, MinIO и полевой конвейер не заменяются этими HTTP-тестами. Для них сохраняются отдельные интеграционные/полевые проверки проекта.
