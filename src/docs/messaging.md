# Событийный обмен

JetStream хранит события потока `SMARTMETRIX_EVENTS` на subjects `smartmetrix.v1.>`.
Subject имеет форму `smartmetrix.v1.<event-name>`; имена событий записываются в kebab-case.
`smartmetrix.v1.dead-letter` зарезервирован для событий, исчерпавших попытки обработки.

Каждое событие передаётся в `EventEnvelope<T>` с обязательными полями `eventId`,
`schemaVersion`, `occurredAt`, `correlationId` и `data`. Текущая версия — `1`.
Потребитель обязан явно отклонить неизвестную версию. Максимальный размер envelope —
256 KiB; кадры, маски и облака точек передаются только ссылками на объектное хранилище.

## Надёжность

- Публикация выполняется через transactional outbox. Реализация хранилища приложения
  должна добавлять outbox-запись в ту же транзакцию, что и изменение агрегата.
- `OutboxDispatcher` удаляет запись только после JetStream publish acknowledgement;
  `Nats-Msg-Id` равен `eventId`, поэтому повтор publish дедуплицируется сервером.
- Durable pull consumer сохраняет позицию на сервере и подтверждает сообщение только
  после успешной обработки.
- Inbox имеет уникальный ключ `(consumer_name, event_id)`: повторная доставка считается
  успешно обработанной без повторного вызова бизнес-логики.
- Политика consumer: explicit ack, пять доставок и backoff 1s, 5s, 30s, 2m, 10m.
  После последней неудачи исходный envelope вместе с причиной публикуется в dead-letter subject.

In-memory inbox/outbox зарегистрированы только как безопасные значения по умолчанию для
локальной разработки и тестов. Сервисы с доменными изменениями должны заменить их
персистентной реализацией и обеспечить уникальные индексы inbox/outbox в PostgreSQL.
