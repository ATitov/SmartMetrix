# Телеметрия, рабочие циклы и сменный отчёт

Первая программная часть #25, #28 и #35: нормализованный контракт, воспроизведение
JSONL, правила фаз, реестр циклов, сменный JSON/CSV-отчёт и контроль целостности.
Реализован также [веб-просмотр сохранённых отчётов](excavator-web.md) в ApiGateway.
Прямой CAN/OEM-адаптер, полевые данные, связка с картой породы
и корректировки оператора с аудитом остаются следующими этапами. Тикеты не закрываются
этим локальным сценарием.

## Запуск

Из корня репозитория:

```powershell
dotnet run --project tools/SmartMetrix.ExcavatorReplay --configuration Release
```

Встроенный синтетический сценарий длится 120 секунд: два полных цикла, один
прерванный обрывом, одно повторное событие. Пропуск с 08:01:01 до 08:01:10 даёт
9 секунд Unknown, а не время погрузки. Ожидаемое покрытие — 92,5%.
Даты сценария — 04.10.2026, 08:00–08:02, UTC+06:00.

Свой записанный поток:

```powershell
dotnet run --project tools/SmartMetrix.ExcavatorReplay --configuration Release -- `
  --input C:\records\machine.jsonl `
  --output artifacts/excavator-replay `
  --start 2026-10-04T08:00:00+06:00 `
  --end 2026-10-04T20:00:00+06:00 `
  --max-gap 3
```

Для собственного файла обе границы смены обязательны. Интервал полуоткрытый
`[start, end)`, UTC-смещение у обеих границ одинаковое. Запись должна покрывать
полные циклы вокруг границ смены; иначе они будут неполными. Смена идентифицируется
машиной и временными границами. Здесь используется фиксированное смещение,
а не база часовых поясов с переходами летнего времени.

## Веб-просмотр и API

Обновлено 04.10.2026. Отдельный локальный стенд запускается из корня проекта:

```powershell
dotnet restore SmartMetrix.sln --locked-mode
pwsh -File deploy/local/start-excavation-web.ps1
```

Скрипт собирает Release, воспроизводит встроенный сценарий и запускает ApiGateway
на `http://127.0.0.1:5191`. Экран — `/excavation/`, вход — `/login/`.
Имя оператора, пароли и порт записаны в
`artifacts/excavation-web/credentials.local.json`. После готовой Release-сборки
можно передать `-NoBuild`; для другого порта — `-Port 5192`.
Остановка: `pwsh -File deploy/local/stop-excavation-web.ps1`.

Экран показывает границы смены в смещении отчёта, длительности фаз, timeline,
покрытие, полные/прерванные/неполные циклы, фильтр и подробности цикла.
Доступны происхождение данных, SHA-256 входа и экспорт CSV. Синтетический
и записанный потоки обозначаются явно. При смене области старые показатели
сбрасываются; отсутствующий или повреждённый отчёт не подменяется демозначениями.

Для подключения готовых replay к существующему Gateway задайте
`ExcavationReports:Roots:<scopeId>` — каталог с подкаталогами прогонов.
Например, переменная `ExcavationReports__Roots__demo-excavator` указывает на
`artifacts/excavator-replay` через абсолютный путь. Относительные пути разрешаются
от content root Gateway. `Workstations:Scopes` должен содержать ту же область,
а её `ExcavatorId` — совпадать с отчётом.

Маршруты требуют аутентификацию, доступную роль АРМ и назначенную область:

| Метод и маршрут | Результат |
|---|---|
| GET `/api/v1/scopes/{scopeId}/excavation/runs` | Список прогонов, `state`, `invalidCount`, `truncated` |
| GET `/api/v1/scopes/{scopeId}/excavation/runs/{runId}/report` | `runId`, `inputSha256`, сменный отчёт |
| GET `/api/v1/scopes/{scopeId}/excavation/runs/{runId}/csv` | CSV, сформированный из проверенного JSON-отчёта |

`runId` — 64 строчных hex-символа. Список имеет состояния `NotConfigured`,
`Unavailable`, `Ready`, `Degraded` и просматривает максимум 1000 каталогов.
Gateway сверяет manifest, SHA-256 `shift-report.json` и метаданные отчёта;
он не проверяет все остальные артефакты replay при каждом HTTP-запросе.
Ошибочный ID даёт 400, отсутствующая настройка — 409 `ReplayNotConfigured`,
отсутствующий или чужой прогон — 404 `ReplayNotFound`, повреждённый отчёт —
409 `ReplayArtifactsInvalid`. Общий доступ описан в [workstation-api.md](workstation-api.md).

## Контракт JSONL v1

Каждая строка — один полный снимок согласованных сигналов первичного источника.
Все поля обязательны; недоступные значения сигналов записываются явно как `null`.
Пустые строки, неизвестные поля, некорректная схема и конфликт EventId отклоняются.

```json
{"schemaVersion":1,"eventId":"00000000-0000-0000-0000-000000000001","excavatorId":"excavator-1","sourceId":"machine-bridge-v1","clockId":"camera-clock","hardwareTimestampNanoseconds":0,"recordedAt":"2026-10-04T08:00:00+06:00","isSynthetic":true,"quality":"Good","engineRunning":true,"toolEngaged":true,"dischargeActive":false,"loadPresent":false,"swingDegreesPerSecond":0,"travelMetresPerSecond":0}
```

| Поле | Семантика |
|---|---|
| eventId | Стабильный UUID события; одинаковый повтор допускается, изменённый повтор отклоняется |
| excavatorId/sourceId/clockId | Один экскаватор, первичный источник и аппаратная шкала на файл |
| hardwareTimestampNanoseconds | Наносекунды единой аппаратной шкалы; строго возрастают у новых событий |
| recordedAt | Время наблюдения, уже сопоставленное аппаратной шкале; не время получения пакета |
| isSynthetic | Обязательный признак синтетики; смешивать режимы нельзя |
| quality | Good, Degraded или Unavailable; два последних дают Unknown |
| engineRunning | Состояние двигателя; выключенный двигатель даёт Waiting |
| toolEngaged | Подтверждённое взаимодействие инструмента с материалом, не просто движение стрелы |
| dischargeActive | Подтверждённая разгрузка материала, не просто угол ковша |
| loadPresent | Подтверждённое наличие груза; это не масса |
| swingDegreesPerSecond | Угловая скорость поворотной платформы в градусах/с |
| travelMetresPerSecond | Скорость перемещения основания в м/с |

OEM/CAN-bridge должен документировать, как получены ToolEngaged, DischargeActive
и LoadPresent, их задержки и ограничения. Правила не определяют эти признаки
из давления или положения ковша автоматически. Отсутствующие сигналы нельзя
заменять false. Алгоритм не объединяет разные источники в один снимок.

Разность RecordedAt и аппаратного времени проверяется по каждому интервалу:
допустимое расхождение по умолчанию 0,05 с. Это проверка согласованности, не
реализация GPS/PTP/UTC-преобразования и не доказательство точности синхронизации
с камерами. Числовые сигналы должны быть конечными. Лимиты файла — 64 MiB,
100 000 наблюдений, 16 384 символа в строке.

## Фазы и циклы

Версия алгоритма: `signal-rules-v1`. Порог поворота — 1 градус/с, движения —
0,05 м/с; допустимый интервал между наблюдениями — 3 с. Порог сравнивается строго
через `>`. Параметры записываются в manifest.

- Digging: ToolEngaged, без одновременного поворота или разгрузки.
- LoadedSwing: поворот с грузом.
- Unloading: подтверждённая разгрузка.
- Returning: поворот без груза.
- Waiting: отсутствие рабочих действий либо выключенный двигатель. Причина
  ожидания при работающем двигателе остаётся неизвестной.
- Unknown: движение основания, отсутствующие/некачественные/противоречивые
  сигналы, неподвижный груз или пропуск телеметрии.

Фаза предыдущего наблюдения действует до следующего, если интервал не превышает
MaximumGapSeconds. Более длинный интервал целиком Unknown. За пределами записи
время также Unknown; последний отсчёт не экстраполируется. Confidence 1 означает
совпадение с детерминированным правилом, не статистическую вероятность и не
полевую оценку точности. Debounce и обучение на реальных сменах пока не реализованы.

Полный цикл требует порядка Digging → LoadedSwing → Unloading → Returning и
подтверждённого перехода к Waiting/Digging. Пропуск, неизвестная или неожиданная
фаза прерывает цикл. Незавершённый на конце записи цикл — Incomplete. Фрагмент
записи, начинающийся после копания, не считается новым циклом.
CycleId равен EventId первого отсчёта Digging, поэтому повтор обработки стабилен.

## Отчёт и воспроизводимость

Каждый запуск создаёт каталог `artifacts/excavator-replay/<runId>`:

- `telemetry.jsonl` — неизменённая копия входного файла;
- `cycles.json` — источники, полный timeline, циклы, число повторов;
- `shift-report.json` — фазы в границах смены, циклы, покрытие, источники;
- `shift-report.csv` — одна строка итогов смены;
- `manifest.json` — SHA-256 артефактов и входа, версия правил, параметры и границы.

RunId вычисляется по хэшу входа, версии правил, параметрам и смене. Готовый каталог
публикуется после записи всех файлов через переименование; сбой может оставить
`.partial-*`. Повтор сверяет содержимое готовых файлов и возвращает тот же каталог.
Повреждение вызывает ошибку, не перезапись. После изменения правил необходимо
повысить AlgorithmVersion.

StartedCycles учитываются по началу, Completed/Interrupted — по завершению в
`[start, end)`. Завершение точно на границе относится к следующей смене; полный
цикл сохранён в её provenance. Сумма длительностей фаз равна длительности смены.
Покрытие — доля времени с известной фазой. Это покрытие телеметрии, не площадь
съёмки породы и не коэффициент полезного использования машины.

MassTonnes, TonnesPerHour и LitresPerTonne равны null, в CSV — пустые поля.
Зоны негабарита и измерения породы пока не привязаны. Программа не выдаёт
синтетические прогоны за готовность оборудования.

## Проверки

```powershell
dotnet test tests/SmartMetrix.ArchitectureTests --configuration Release `
  --filter FullyQualifiedName~ExcavationTests
```

Проверяются повторы/конфликты, несовместимые часы/источники, пропуски,
неполные/прерванные циклы, границы смен, CSV, повтор запуска и повреждение файлов.
