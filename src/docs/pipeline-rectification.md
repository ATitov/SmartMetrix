# Применение карт калибровки в измерительном конвейере

Поддерживаются карты, созданные `tools/camera-calibration`: NPZ с четырьмя массивами
`leftX`, `leftY`, `rightX`, `rightY` (float32, little-endian, C-order, height×width).
На вход поступают исходные packed Mono8 кадры A/B/C одинакового разрешения.
Python и OpenCV на машине DepthService не нужны: чтение NPZ/NPY и remap реализованы в .NET.

## Поток координат

1. Оркестратор сохраняет активную калибровку, включая `rectification`, в checkpoint.
2. Контроль качества и сегментация работают по исходным кадрам; маска относится к исходной A.
3. DepthService загружает карты AB, AC и BC из `Depth:CalibrationDirectory`, проверяет SHA-256
   из snapshot калибровки, формат и размеры. Произвольные URL, абсолютные пути, `..`
   и символьные ссылки/ junction не допускаются.
4. Каждая пара отдельно ректифицируется билинейной интерполяцией. Для disparity используются
   её собственные fx/fy/cx/cy и базис из P1/P2, а не исходные intrinsics камеры.
5. Точки AB/AC переходят из ректифицированной A в исходную A через R1ᵀ.
   Для BC применяются поворот `rotationCameraBToA × R1ᵀ` и положение B в координатах A.
   Затем все точки переходят в риг через `cameraA.rotation`/`translation`.
   Для AB/AC исходный пиксель задают leftX/leftY; BC проецируется через исходные
   intrinsics и пять коэффициентов дисторсии A из `referenceProjection`.
6. Точка записывается в ближайший исходный пиксель A. При коллизии выигрывает ближайшая
   поверхность по Z камеры A; в пределах 1% глубины — более высокая confidence.
   Пропуски не дорисовываются, их depthConfidence=0. Окна сопоставления, пересекающие
   невалидные области remap, отбрасываются.
7. `organized-cloud.json` и confidence-карта имеют размеры исходной A. Ответ depth содержит
   `pixelGrid=CameraAOriginal` и SHA-256 использованных карт. Перед анализом оркестратор
   проверяет обозначение сетки, чтобы не совместить маску с чужими индексами пикселей.

## Подключение существующего результата

1. Повторно выполните `export-draft` обновлённой утилитой. В новом JSON должен быть
   раздел `rectification` версии 2 с тремя парами, исправленными intrinsics и SHA-256.
   Сохраните старый `calibration-draft.json` под другим именем перед повторным экспортом.
   Старый экспорт без этого раздела сам по себе применение карт не включает.
2. Скопируйте соответствующие `maps-AB.npz`, `maps-AC.npz` и `maps-BC.npz` в каталог DepthService.
   Например `artifacts/calibration/result-01`, содержащий исходный результат утилиты.
3. Перед запуском DepthService задайте абсолютный путь:

```powershell
$env:Depth__CalibrationDirectory = 'C:\Users\Andrey\Documents\SmartMetrix\artifacts\calibration\result-01'
```

4. Перед запуском оркестратора задайте:

```powershell
$env:Pipeline__FramesAreRectified = 'false'
$env:Pipeline__RigId = 'hikvision-1m'
```

5. В CalibrationService настройте ожидаемые базисы 0,25/0,75/1 м, зарегистрируйте
   подготовленный JSON как Draft и после проверки активируйте обычным endpoint:

```powershell
$draft = Get-Content artifacts/calibration/result-01/calibration-draft.json -Raw
$record = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5208/api/calibrations/ -ContentType application/json -Body $draft
$activation = @{ validFrom = [DateTimeOffset]::UtcNow.ToString('o'); actor = 'engineer' } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:5208/api/calibrations/$($record.id)/activate" -ContentType application/json -Body $activation
```

Это пример ручной активации, утилита автоматически её не выполняет. Преобразование
риг → платформа должно быть измерено или явно определено для статического лабораторного стенда.

В edge Compose каталог хоста `SMARTMETRIX_CALIBRATION_ROOT` монтируется в
`/app/calibration` только для чтения, `Depth__CalibrationDirectory` уже задан.
Для нескольких версий можно разместить файлы в подкаталогах и задать относительные
`mapFile` в payload **перед регистрацией**, например `v2/maps-AB.npz`. Не удаляйте
старые карты, если по ним ещё нужны повторы. Для повторяемости важны и SHA, и метаданные:
они входят в checksum/snapshot калибровки, а не берутся из текущих настроек утилиты.

## Ошибки и границы

- `RectificationIntegrityError`: файл отличается от зарегистрированной версии.
- `RectificationMapMissing` / `NotConfigured`: карта не развёрнута или не задан каталог.
- `InvalidRectificationMap`: неверный NPZ/NPY, размер или небезопасный путь.
- `RectificationConflict`: карты включены вместе с `FramesAreRectified=true`.
- `PixelGridMismatch`: depth не подтвердил исходную сетку A.
- Поддерживаются горизонтальные пары AB/AC/BC с положительной disparity и одинаковыми
  intrinsics левого/правого ректифицированного изображения (CALIB_ZERO_DISPARITY).
  Вертикальная стереопара не поддерживается. Версия 1 сохраняет режим AB/AC;
  версия 2 требует все три пары и не переходит молча на две при ошибке карт.
- Нельзя подменять исходные intrinsics ректифицированными в `cameras`: они сохраняются
  исходными, а исправленные параметры находятся в `rectification.pairs`.
- RTSP остаётся режимом тестового захвата: наличие карт не создаёт аппаратной метки
  экспозиции или позы. Ограничение `UnsynchronizedTestCapture` сохраняется. Для проверки
  полного пути можно воспроизводить сохранённые кадры через Simulator с соответствующей
  калибровкой и явно заданной тестовой позой.
- Перенос в ближайший пиксель даёт дискретизацию до 0,5 px по каждой оси и может оставить
  отверстия. Это не сглаживание/интерполяция глубины через границы блоков.
- Ректификация выполняется на CPU и загружает карты на каждый запрос. Прогон на полном
  разрешении 3200×1800 и GPU ещё требуется; существующие HTTP/JSON ограничения остаются.

Проверки: unit-тесты remap, геометрии, слияния, целостности и границ; HTTP-тест от
активной калибровки до Completed с разными картами AB/AC/BC и анализом на исходной сетке A.
BC может заполнить пробелы и дать более уверенные точки; прирост качества нужно измерить
на реальных сценах. Третий стереорасчёт увеличивает время обработки.
