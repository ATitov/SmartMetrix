# Локальное развёртывание SmartMetrix на Windows

Полный прикладной контур запускается как набор отдельных .NET-процессов.
Штатное развёртывание публикует сервисы и инфраструктуру в `C:\DEPLOY\SmartMetrix`.
Локальный профиль по умолчанию использует файловое хранение метаданных;
PostgreSQL поддерживается через `Persistence__Provider=Postgres` и
`ConnectionStrings__SmartMetrix` в сервисах с соответствующей реализацией.
Состав хранилищ описан в [data-layer.md](data-layer.md).

Обновлено 04.10.2026. Требуются PowerShell 7 и .NET SDK из `global.json`.
Перед первой сборкой выполните `dotnet restore SmartMetrix.sln --locked-mode` из корня проекта.

По умолчанию запускается HTTP-конвейер обработки. Перед измерением задайте `Pipeline__RigId`
и загрузите калибровку и позиционные отсчёты. Настройка и синтетический стенд описаны в
[measurement-pipeline.md](measurement-pipeline.md). Демонстрация интерфейса с переходами по таймеру
включается отдельно переменной `MeasurementWorkflow__RunDemoPipeline=true` перед запуском с `-TestMode`.
Без `-TestMode` скрипт выбирает Arena и StoneVision; недоступное оборудование не заменяется симулятором.

```powershell
.\deploy\local\deploy.ps1
C:\DEPLOY\SmartMetrix\start.ps1
C:\DEPLOY\SmartMetrix\status.ps1
C:\DEPLOY\SmartMetrix\stop.ps1
```

Для автозапуска выполните `install-autostart.ps1` из обычной сессии пользователя, который будет
управлять локальным контуром. Задачи запускаются при входе этого пользователя без повышения прав,
поэтому ручные `start.ps1` и `stop.ps1` работают в том же контексте. Повторно запустите установку
после обновления со старой версии, чтобы заменить задачи, ранее зарегистрированные от `SYSTEM`.

PID-файлы содержат PID, время запуска и ожидаемый путь процесса. Повреждённые и устаревшие файлы
считаются недоверенными: скрипты не завершают процесс только по совпавшему числовому PID.
Штатный `stop.ps1` создаёт маркер намеренной остановки, поэтому watchdog не перезапускает контур.
Явный `start.ps1` или запуск при следующем входе пользователя снимает этот маркер.

Вход: `http://127.0.0.1:5190/login/`. Рабочие панели используют учётную запись и сессию.
Операторская панель: `http://127.0.0.1:5190/operator/`.
Инженерная панель: `http://127.0.0.1:5190/engineer/`.

## Изолированный запуск из рабочего каталога

`pwsh -File deploy/local/start-workspace.ps1` собирает Release и запускает 14 сервисов,
MinIO и NATS с данными в `data/workspace-run`. Требуются .NET 10 SDK, PowerShell 7
и установленные бинарники `C:/DEPLOY/SmartMetrix/infrastructure/minio.exe`, `nats-server.exe`.
Занятые порты приводят к отказу запуска; чужие процессы не останавливаются.
Повторная сборка пропускается параметром `-NoBuild`.

Вход в панели: пользователь `engineer`, пароль — поле `engineerPassword` в
`data/workspace-run/credentials.json`. Файл также содержит отдельные административные
и инфраструктурные секреты; он не предназначен для публикации.

Запуск использует локальный профиль хранения, Arena и StoneVision, без демозаписей.
Область `local` содержит явные значения `UNCONFIGURED`: перед реальными измерениями
нужно указать оборудование, участок, систему координат, RigId и загрузить калибровку.
Запущенные HTTP-сервисы сами по себе не подтверждают готовность измерительного конвейера.

Опубликованные сервисы, инфраструктурные бинарники и runtime-данные находятся в `C:\DEPLOY\SmartMetrix`. Структурированные JSONL-логи каждого сервиса записываются в отдельный каталог `C:\DEPLOY_LOG\SmartMetrix.<ServiceName>\`; файл меняется ежедневно и называется `yyyy-MM-dd.jsonl`. Порты сервисов заданы в `services.psd1`.

## Дополнительные стенды

Для стенда, подключённого к существующим PostgreSQL/NATS/MinIO, используйте
[start-review-stand.ps1 и его инструкцию](review-stand.md).
Его конфигурация и процессы отделены от штатного deployment.

Для отдельного веб-просмотра синтетических сменных отчётов:

```powershell
pwsh -File deploy/local/start-excavation-web.ps1
pwsh -File deploy/local/stop-excavation-web.ps1
```

Открывайте `http://127.0.0.1:5191/excavation/`; учётные данные находятся в
`artifacts/excavation-web/credentials.local.json`. Порт меняется через `-Port`.
Скрипт запускает только Gateway и создаёт replay; полный измерительный контур
не требуется. Подробности — в [excavator-replay.md](excavator-replay.md).

## Ограничения рабочего компьютера

- Для Arena необходим собранный Windows native-адаптер и настроенные серийные номера трёх камер.
- Для GPU-реконструкции необходим собранный native-модуль OpenCV CUDA/VPI и доступная CUDA-библиотека.
- Для сегментации необходим работающий StoneVision по настроенному `Segmentation:StoneVisionBaseUrl` с загруженными моделями.
- MinIO доступен на `127.0.0.1:9000`, консоль — `127.0.0.1:9001`.
- NATS JetStream доступен на `127.0.0.1:4222`, мониторинг — `127.0.0.1:8222`.
