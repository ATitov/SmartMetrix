# Калибровка камер SmartMetrix

После калибровки: [сравнение карт глубины AB/AC/BC и их объединения](DEPTH-COMPARISON.md).

## Десктопное окно Windows

Запуск: `tools/camera-calibration/calibration-gui.ps1` из корня проекта.
Нужны подготовленное окружение ниже и Python с Tkinter.

1. **Сессия:** выберите существующий каталог или задайте новый путь и создайте шаблон.
   Откройте SVG для печати; проверьте реальные размеры. Параметры клеток в окне
   используются при создании; настройки существующей сессии находятся в `session.json`.
2. **Снимки:** подтвердите неподвижность и захватите A/B/C через CameraService
   либо выберите три сохранённых изображения и импортируйте положение.
3. **Расчёт:** выберите родительский каталог результатов и запустите калибровку.
   Создаётся отдельный каталог. Откройте отчёт и проверьте качество.
4. **Экспорт:** укажите преобразование риг → платформа в JSON или явно выберите
   лабораторную систему, совпадающую с A. Экспортируется Draft без регистрации/активации.
   Кнопка сравнения открывает отдельное окно: в нём выберите полученный каталог результата.

Журнал и индикатор обновляются во время работы. Настройки и закрытие окна блокируются
до завершения операции. Прямой захват Arena выполняется вне утилиты; здесь доступен импорт.

Консольная утилита Python/OpenCV для трёх камер Arena или IP. Работает по сохранённым
изображениям и не требует оборудования для запуска/подготовки шаблона.
Рассчитывает intrinsics/distortion каждой камеры, позы B/C относительно A, независимые
базисы AB/AC/BC, карты ректификации пар, RMS по кадрам и согласованность трёх пар.
Для распознавания соответствующих точек используется ChArUco с уникальными ID.

## Установка

Python 3.12, из корня репозитория:

```powershell
python -m venv tools/camera-calibration/.venv
tools/camera-calibration/.venv/Scripts/python.exe -m pip install -r tools/camera-calibration/requirements.txt
```

На текущем компьютере окружение уже подготовлено. Команды ниже запускаются из корня проекта.
На Linux используйте `.venv/bin/python calibrate.py ...` вместо `run.ps1`.

## 1. Создать сессию и шаблон

```powershell
tools/camera-calibration/run.ps1 init artifacts/calibration/hikvision --rig-id hikvision-1m
```

Создаются `session.json`, `board.png`, `board-print.svg`, каталог `views`.
Шаблон по умолчанию: 10×7 **клеток**, клетка 80 мм, маркер 60 мм, общий размер 800×560 мм.
Распечатайте SVG с масштабом 100%, без «вписать в страницу», на плоском жёстком основании.
Оставьте белое поле вокруг шаблона. Линейкой проверьте реальный шаг клеток по нескольким
клеткам в обоих направлениях. При изменении физического размера исправьте `squareMetres`
и `markerMetres` до съёмки; неправильный размер пропорционально исказит все базисы.
Для другого шаблона создайте новую сессию с `--columns`, `--rows`, `--square-mm`.

В `session.json` задана наша линейная рама: **AB=0,25 м, BC=0,75 м, AC=1 м**.
Это ожидаемые значения для проверки, не принудительное ограничение решения:
фактические расстояния утилита вычисляет по кадрам. При другой раме измените ожидаемые
значения и допуски **до съёмки**, не подгоняйте их под плохой результат.

## 2. Собрать не менее 15–25 положений шаблона

После установки камеры не перемещать. Зафиксируйте разрешение, фокус и режим день/ночь.
Показывайте шаблон на разных расстояниях, с наклонами вокруг обеих осей, в центре и
ближе к краям изображения. Сохраняйте резкость и видимость общих точек во всех камерах.
Для Hikvision 4 мм начните с расстояния больше 3,1 м; подберите размер шаблона так,
чтобы маркеры уверенно распознавались. Небольшой лист A4 на 5–8 м может оказаться слишком мелким.

Для RTSP, при запущенном CameraService и настроенных A/B/C:

```powershell
tools/camera-calibration/run.ps1 capture artifacts/calibration/hikvision --stationary-confirmed
```

Один вызов = одно положение. Держите шаблон и камеры неподвижно до завершения команды:
CameraService последовательно обслуживает тестовые снимки, синхронность не предполагается.
Пароли остаются в конфигурации CameraService, утилита их не запрашивает и не сохраняет.
Порядок настройки сервиса — [RTSP инструкция](../../src/docs/rtsp-camera.md).

Для Arena или уже записанных изображений скопируйте кадры в структуру:

```text
views/
  001/A.png  001/B.png  001/C.png
  002/A.png  002/B.png  002/C.png
  ...
```

В каждой папке — один и тот же неподвижный шаблон в одном положении. Поддерживаются
PNG, JPEG, PGM, TIFF и packed Mono8 `.raw`. Для RAW укажите `rawImageSize: [3200,1800]`
в `session.json` (реальные размеры, не обязательно этот пример). Не меняйте размер
кадров и не подменяйте кадры камер. Прямой захват Arena утилита не выполняет:
используйте CameraService и выгрузку кадров из StorageService.

## 3. Рассчитать калибровку

```powershell
tools/camera-calibration/run.ps1 calibrate artifacts/calibration/hikvision --output artifacts/calibration/result-01
```

Каталог результата должен быть новым: предыдущие результаты не перезаписываются.
Выходные файлы:

- `report.html` — таблица ошибок, результат проверок, изображения с найденными углами;
- `detection-report.json` — отброшенные кадры и контрольные суммы входов;
- `calibration.json` — параметры, позы, ошибки каждого положения, конфигурация и версия OpenCV;
- `maps-AB.npz`, `maps-AC.npz`, `maps-BC.npz` — float32 карты X/Y обеих камер;
- `maps-A.json`, `maps-B.json`, `maps-C.json` — манифесты карт с SHA-256.

Проверяются минимум общих наблюдений, RMS ≤ 1 px по каждой камере и паре,
охват изображения ≥35% по обеим осям, отклонение базисов ≤2 см,
замыкание цепочки поз (≤2 см и ≤1°). Точные дубли троек исключаются.
Коды завершения: 0 — проверки пройдены, 2 — расчёт выполнен, качество не прошло,
1 — недостаточно данных/ошибка. При недостатке точек смотрите detection-report.json.
Утилита не удаляет автоматически неудобные кадры ради уменьшения RMS.

**PASS не является метрологической аттестацией:** ошибки рассчитаны на обучающем
наборе. Проверьте отдельные кадры, известные расстояния и размеры, осмотрите распределение
точек по полю кадра. Набор похожих фронтальных видов недостаточен даже при малой RMS.

## 4. Проверить ректификацию

```powershell
tools/camera-calibration/run.ps1 rectify artifacts/calibration/result-01 --pair AB --left artifacts/calibration/hikvision/views/001/A.png --right artifacts/calibration/hikvision/views/001/B.png --output artifacts/calibration/check-AB
```

Получатся `left.png`, `right.png`. Матрицы R1/R2/P1/P2/Q и область валидных пикселей
хранятся в calibration.json. **У каждой пары собственная сетка ректификации.**
Нельзя напрямую объединять AB, AC и BC по индексам пикселей. DepthService теперь применяет
карты каждой пары и переносит 3D-точки обратно в исходную пиксельную сетку A, где
рассчитывается сегментация. Для этого экспорту нужен раздел `rectification` (следующий шаг).
В оркестраторе оставьте `FramesAreRectified=false`: на вход подаются исходные кадры.

## 5. Экспортировать черновик в формат CalibrationService

Система рига совпадает с **исходной камерой A**: X вправо, Y вниз, Z вперёд, метры.
`rotationCameraToRig` и `centreInRigMetres` переводят координаты камеры в риг.
Преобразование риг → платформа эта утилита не измеряет. Задайте его отдельным JSON
с `rotation` (9 чисел, матрица построчно) и `translation` (3 числа, метры).
Для самостоятельного лабораторного стенда, где платформа определена как камера A:

```json
{"rotation":[1,0,0,0,1,0,0,0,1],"translation":[0,0,0]}
```

```powershell
tools/camera-calibration/run.ps1 export-draft artifacts/calibration/result-01 --rig-to-platform artifacts/calibration/rig-to-platform.json
```

Получится `calibration-draft.json`. Можно добавить `--service http://127.0.0.1:5208`
для регистрации **Draft**; автоматической активации нет. Для принятой рамы перед запуском
CalibrationService задайте:

```powershell
$env:Calibration__ExpectedGeometry__AbMetres = '0.25'
$env:Calibration__ExpectedGeometry__BcMetres = '0.75'
$env:Calibration__ExpectedGeometry__AcMetres = '1.0'
```

Старые значения сервиса по умолчанию сохранены для совместимости: 0,7/0,8/1,5 м.
Экспорт включает `rectification` версии 2 для AB/AC/BC с относительными именами NPZ,
SHA-256, исправленными intrinsics пар, поворотом и смещением из ректифицированной
левой камеры каждой пары в исходную A. `referenceProjection` содержит исходные
intrinsics и дисторсию A для перепроекции BC. DepthService
использует именно этот раздел; старые `rectificationMapUri` оставлены как ссылки на
диагностические манифесты, они не используются для чтения карт в новом пути.

Разместите `maps-AB.npz`, `maps-AC.npz` и `maps-BC.npz` на машине DepthService и перед его запуском задайте:

```powershell
$env:Depth__CalibrationDirectory = 'C:\Users\Andrey\Documents\SmartMetrix\artifacts\calibration\result-01'
$env:Pipeline__FramesAreRectified = 'false'
```

Первую переменную читает DepthService, вторую — MeasurementOrchestrator. Для контейнера
смонтируйте каталог только для чтения: edge Compose использует
`SMARTMETRIX_CALIBRATION_ROOT` → `/app/calibration`. Файлы проверяются по SHA-256 при
каждой реконструкции; менять их после экспорта нельзя. Для новой калибровки используйте
новый каталог, сохраняйте старые файлы для повторной обработки.

После проверки отчёта зарегистрируйте и активируйте калибровку через CalibrationService.
Если черновик был экспортирован старой утилитой без `rectification`, сохраните его
отдельно и повторите экспорт из исходного результата. Подробный порядок и ограничения:
[карты в измерительном конвейере](../../src/docs/pipeline-rectification.md).

## Проверки разработки

```powershell
tools/camera-calibration/.venv/Scripts/python.exe -m unittest discover -s tools/camera-calibration -p test_calibrate.py -v
```

Тесты используют известную синтетическую геометрию, проверяют знак и единицы трансляции,
восстановление intrinsics, эпиполярное выравнивание, детектор печатного шаблона и отказы.
Это не испытание конкретной камеры.

Алгоритмы: [OpenCV ChArUco](https://docs.opencv.org/4.12.0/da/d13/tutorial_aruco_calibration.html),
[стереокалибровка и ректификация](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html).
