# Сравнение карт глубины

## Графическое окно Windows

Запустите `tools/camera-calibration/compare-depth-gui.ps1` из корня проекта.
Выберите каталог калибровки, кадры A/B/C и каталог результатов, затем нажмите
«Сравнить». «Загрузить демо» заполняет поля существующим синтетическим набором.
В окне доступны журнал, таблица метрик и просмотр карты выбранной строки.
Кнопка «Открыть HTML-отчёт» показывает полный отчёт в браузере.
Каждый запуск создаёт новый подкаталог. Пока идёт расчёт, настройки и закрытие
окна заблокированы; интерфейс продолжает обновляться. Требуется Python с Tkinter.

## Консольный запуск

Утилита запускает CPU-алгоритм рабочего DepthService для AB, AC, BC, AB+AC и AB+AC+BC.
Сервисы и подключённые камеры не требуются. Используйте неподвижную сцену и кадры
одной серии: утилита не проверяет синхронность.

Требуются .NET 10 и Python-окружение из [README](README.md). Каталог калибровки
должен содержать `calibration-draft.json` с rectification версии 2 и три NPZ-карты.
Вход: исходные 8-битные PNG/JPEG точного разрешения калибровки; цвет переводится в серый.
Изменение размера не выполняется.

Из корня проекта:

```powershell
tools/camera-calibration/compare-depth.ps1 artifacts/calibration/result-01 `
  --a artifacts/capture/A.png --b artifacts/capture/B.png --c artifacts/capture/C.png `
  --output artifacts/depth-comparison/run-01 --near 1 --far 20 --max-disparity 96
```

По умолчанию выполняется Release-сборка. После первой сборки можно добавить `--no-build`.
Выходной каталог должен быть новым; существующие результаты не перезаписываются.
При ошибке может остаться неполный каталог; для повтора выберите новый.

Откройте `report.html`: пять карт с общей шкалой глубины, карты confidence,
заполнение, медианная глубина, средняя confidence, время и вклад BC относительно AB+AC.
Все результаты находятся в исходной пиксельной сетке A. Z — оптическая глубина от A,
а не расстояние по лучу или высота в мировых координатах.
`report.json` содержит настройки, SHA-256 кадров, калибровки и карт.
NPZ каждого режима содержит `depthMetres`, `confidence`, `valid`. Используйте маску
`valid`: нули в невалидных точках не являются измерениями.

Для проверки точности поставьте плоскую мишень параллельно плоскости изображения A,
измерьте её Z и добавьте параметры, например `--roi 800 500 400 300 --reference-depth 5`.
ROI задаётся как X Y ширина высота в исходном кадре A и должна лежать внутри мишени.
В отчёт добавятся смещение, MAE, RMSE и 95-й процентиль абсолютной ошибки в метрах.
Ошибки считаются по валидным точкам ROI, поэтому сравнивайте их вместе с заполнением.
Без эталона заполнение и confidence не доказывают точность. Разброс глубины сцены
не является оценкой шума; для повторяемости нужны несколько серий одной сцены.

Время — один замер после прогрева AB: загрузка и проверка карт, remap, stereo и слияние.
Запуск процесса и запись результатов исключены. Кеш ОС и JIT могут влиять на результат;
это диагностическое сравнение, не строгий бенчмарк. Полное разрешение на CPU требует
значительного времени и памяти. Диапазон disparity должен охватывать fx*baseline/Z
каждой пары для интересующих расстояний, независимо от near/far.

Проверка синтетической плоскостью с известной глубиной:

```powershell
dotnet build tools/SmartMetrix.DepthComparison/SmartMetrix.DepthComparison.csproj -c Release
tools/camera-calibration/.venv/Scripts/python.exe -m unittest discover -s tools/camera-calibration -p test_compare_depth.py -v
```
